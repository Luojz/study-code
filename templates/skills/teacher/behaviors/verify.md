# Behavior: Verify — 提问验证

通过提问检验新人的理解程度，更新覆盖率层级。

## 出题策略

### 概念题
测试对函数职责的理解。
```
"你能用自己的话说说 initBridge() 这个函数是干什么的吗？"
```

### 场景题
测试对边界条件和异常处理的理解。
```
"如果用户在请求还没返回的时候就关闭了页面，代码会怎么处理？"
```

### 设计题
测试对设计意图的理解。
```
"你觉得这里为什么要用回调而不是直接同步调用？"
```

## 评分规则

| 回答质量 | 覆盖率更新 | 后续动作 |
|----------|-----------|---------|
| 完全正确 | min(level + 1, 2) | "对！继续" |
| 部分正确（遗漏但不错误）| level 不变 | 补充讲解 |
| 有错误理解 | level 不变 | 换角度重新讲 |
| "不确定/忘了" | level 不变 | 重新讲解该知识点 |

注意：verify 提问最高只能提升到 level 2（能复述）。Level 3 需通过 practice，Level 4 需通过 simulate。

## 提问时机

由 config.yaml 的 question_frequency 控制：
- `high`: 每个函数后问 1 个问题
- `medium`: 每 2-3 个函数问 1 个问题
- `low`: 每个模块问 1 个问题
- `off`: 不主动提问

用户说"别问了"时暂停，下一个学习单元恢复。
