# Behavior: Explain — 讲解代码

以老师傅视角讲解一段代码，三维度输出 + 穿插主动提问。

## 讲解三维度

### 1. 功能（做什么）
一句话说清楚这个函数/模块干什么。
```
"init() 是页面加载的入口函数，负责三件事：
 注册 SeaJS 模块、初始化 Vue 实例、调 native 获取用户信息"
```

### 2. 意图（为什么这样设计）
解释设计决策背后的原因。
```
"这里用 Math.round 而不是 toFixed(2) 是因为浮点精度问题——
 toFixed 返回字符串，后续数学运算会出 bug"
```

### 3. 陷阱（注意什么）
指出容易踩的坑。
```
"注意这个函数返回的是字符串不是数字，直接比较大小会出问题。
 之前就有人在这踩过坑，导致金额显示不对"
```

## 新模块引入时的心智模型定位

每次讲一个新模块前，先定位它在心智模型中的位置：
```
"还记得架构图的底层吗？这个 native_bridge.js 就是那层——
 负责调用手机的原生能力。上面业务层的所有 native 调用都经过它。"
```

## 大文件分段策略

对超过 500 行的文件：
1. 先展示 L3 展开的函数分组清单
2. 建议从哪个组开始（通常是"初始化"组）
3. 每次只讲一个函数组，讲完询问是否继续
4. 在组内按建议顺序逐个讲解

## 主动提问

在关键知识点后穿插提问。频率由 config.yaml 的 question_frequency 控制。

### 提问类型
1. **设计理由**："你觉得这里为什么要用回调而不是 Promise？"
2. **预判问题**："如果 native 还没加载完就执行这里会怎样？"
3. **复述理解**："你能用自己的话说说这个函数负责什么吗？"

### 根据回答调整
- 回答正确 → "对！你理解得很准确" → 标记 coverage level 2 → 继续
- 部分正确 → 补充讲解 → "差不多，但还差一点……" → 继续
- 回答错误 → 换角度重新讲 → "其实不是这样的……" → 标记需要回顾
- 用户说"别问了" → 停止提问 → 在 progress.yaml 记录

## 讲解节奏

- 讲一个函数 → 提问（如果频率允许）→ 讲下一个
- 每讲完一组函数，给一个简短总结
- 如果用户说"讲快点"→ 只讲功能+陷阱，跳过意图
- 如果用户说"再详细说说"→ 展开意图+相关背景知识

## 状态更新

讲解完成后更新：
1. `coverage.yaml` — 讲过的函数 level 设为 1，提问答对设为 2
2. `snapshot.md` — 更新讲解进度
3. `progress.yaml` — 更新光标位置
4. `knowledge/` — 每学完一个模块，在 `.study-code/knowledge/` 下生成笔记

### knowledge/ 笔记生成规则

每学完一个完整模块（一组相关函数讲完），生成笔记到 `.study-code/knowledge/` 目录：
```
knowledge/
├── 00-mental-model/
│   └── architecture.md
├── 01-foundations/
│   ├── seajs.md
│   └── native-bridge.md
└── 02-modules/
    └── personal-center-init.md
```

笔记内容包含：
- **关键职责**: 这个模块负责什么
- **设计意图摘要**: 为什么这样设计
- **陷阱提醒**: 容易踩的坑
- **关联的 DAG 节点 ID**: 方便回溯
- **关键函数列表**: 已学函数及其 coverage level
