# Behavior: Trace — 功能追踪（模式 A）

从用户描述的功能入口开始，沿调用链追踪完整代码路径。

## 触发条件
用户说：
- "交易按钮怎么实现的"
- "这个功能的完整流程是什么"
- "从点击到结果经历了什么"
- 或任何"XX功能怎么工作"的问题

## 追踪策略

### Step 1: 定位入口
```
1. 理解用户描述的功能
2. 搜索相关 HTML 模板找到触发点（按钮/链接/事件）
3. 从触发点追踪到 JS 事件处理函数
```

### Step 2: 沿调用链展开
```
1. 读取当前函数，找到调用的下一个函数
2. 如果下一个函数在已展开的文件中 → 直接跳到那行
3. 如果在未展开的文件中 → 自动展开到 L2（文件级，不深入函数级）
4. 重复直到到达终点（API 调用 / UI 更新 / 事件完成）
```

### Step 3: 可视化路径
```
用 ASCII 调用链图展示完整路径：

用户点击"交易" → handleClickTrade()
    → checkLogin()          [已学 ✓]
    → jump.action10061()    [已学 ✓]
    → native.openPage()     [未学 ✗ ← 这块要补]
    → 目标页面加载
```

### Step 4: 逐步讲解
```
按路径顺序，对每个节点：
- 如果已学（coverage level ≥ 1）→ 快速回顾
- 如果未学 → 展开讲解（调 explain 行为）
```

## 已学内容快速回顾
```
"这个 checkLogin 你之前学过——检查用户登录态，
 没登录就跳登录页。这里就不重复了。"
```

## 自动展开限制
- 追踪中遇到未展开的文件 → 只展开到 L2（文件级）
- 不自动深入 L3+（函数级），留给用户选择

## 模式 A 结束后
- 将追踪结果写入 roadmap.yaml 的 trace_units
- 更新 coverage.yaml（路径上的函数标记 level 1）
- 更新 snapshot.md
- 建议用户：
  - 回到模式 B 继续（"要回到之前的学习路线吗？"）
  - 或深入追踪中发现的某个节点
